# KBMacro 待办与已知取舍

> 记录"决定不做 / 以后再做"的事情与理由，避免同一件事被重新讨论。
> 与 `docs/flow.md`（当前架构与流程）配套。

## 一、功能待办

### 1. 托盘常驻（收尾阶段）
- 方案：`wxTaskBarIcon` 子类 + 配置项 `closeToTray`（**默认关**）+ 关窗时隐藏窗口并首次弹一次气泡提示，托盘菜单只放「显示主窗口 / 全部停止 / 退出」。
- **只改关闭语义**，最小化仍回任务栏。
- 理由：全局热键已能在后台工作，托盘唯一新增价值是"关窗不退出"。
- 风险：用户点 × 以为退了，但鼠标还在动 → 必须弹气泡 + 托盘菜单显眼。

### 2. 录制过程的实时进度
- 现在只显示"录制中…"。将来由消费端每 N 个动作 / 每秒汇报一次（`CallAfter` 回 UI 更新计数）。

### 3. 录制开始延迟
- 回放/连点器/键盘都有 `RunSpec::startDelayMs`；录制需要独立的 `Config::recordStartDelayMs`（默认 200），用于避开"按下开始热键的手还在键上"。
- 等 Recorder 模块开工时一起做，现在落就是死开关。

### 4. 相对坐标
- `MouseMoveRelative` / `MouseClickRelative` 两个新 `ActionType`，`x`/`y` 解释成 `dx`/`dy`。
- 只影响：枚举 + 表驱动字符串 + 回放 switch。录制端永远产出绝对坐标，不改。
- 注意：相对点击是"在当前点按下去"，不先 `moveTo`——不能和绝对版共用分支。

### 5. 钩子被系统卸掉的检测
- 低级钩子回调超 `LowLevelHooksTimeout`（默认 300ms）会被系统静默卸载，表现为"录着录着不录了"。
- 将来可周期校验钩子有效性（如定期 `UnhookWindowsHookEx` 失败或事件长时间为 0 时提示用户）。

## 四、已知取舍（不是 bug，不用改）

1. **`MouseClick` 回放时先 `moveTo`**：日志里每轮会出现两条 `move to`（脚本的 `MouseMove` + `MouseClick` 内部就位）。多一条事件约 1ms，换"手写脚本也能点对位置"。
2. **Sleep 计时器的节拍误差**：间隔 1000ms 实测约 1025ms，按住 50ms 实测 63ms。原因是 10ms 分片被系统节拍对齐。
3. **干跑不加速**：`ENABLE_DRY_RUN` 下所有等待照常发生，保证时基与真实运行一致。
4. **`HybridTimer` 也弹 CPU 警告**：复用 Spin 那条，未新增确认项。
